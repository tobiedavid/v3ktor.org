# Tests

`node tests/run.js` runs everything. The same command runs on every pull request (`.github/workflows/tests.yml`).

| File | What it checks | Needs |
|---|---|---|
| `threshold/engine.test.js` | One check or more for each of the Threshold Log's reading rules. The rules are read out of the shipped app file, so what is tested is what people open. | Node |
| `gut/repair.test.js` | The Food Trial Log's 13 repair cases, in the English and the French copy. | Node |
| `../tools/threshold/build.js` | `threshold/app/index.html` is exactly what `tools/threshold/src/` and `shared/` build, so the source and the shipped file can't drift apart. | Node |
| `../tools/foods/pack.js` | The Patch and the Food Trial Log (English and French) hold exactly the foods in `data/foods.csv`, and every row of the CSV is whole. | Node |
| `../tools/shared.js` | Every app holds the current copy of each piece in `shared/` (the Nutrition rules). | Node |
| `patch/needs.test.js` | The Patch's daily needs for 131 made-up people (every sex and age, weights, work, smoking, diet, pregnancy, breastfeeding, kidney disease, the muscle goal), its bands and its nutrient list, against `fixtures/patch-needs.json`, recorded before the rules moved to `shared/nutrition.js`. `--record` writes the fixture again, for a change meant to move a need. | Browser |
| `patch/wrench.test.js` | The Patch, English and French: the line above the Nutrition bars and its wrench; changing an answer moves the needs and what is shared on the phone; vegetarian and vegan exclude each other; the newer answer wins between apps, an older one doesn't; The Patch's own pregnancy and diet answers move with the shared ones; a change from another app shows at once; sharing off reads and writes nothing; erasing removes the shared answers. | Browser |
| `gut/nutrition.test.js` | Food Trial Log, English and French: Nutrition on `shared/nutrition.js` (the same 21 rows, no calories, vitamins D and E in « UI » in French); the wrench asks sex, age, weight and the list, without what this app doesn't use; only answered answers are shared; an answer from the old panel counts as given; the newer answer wins and what this app doesn't ask is kept; erasing removes the shared answers; and a round trip on one phone, The Patch to the Food Trial Log and back. | Browser |
| `threshold/nutrition.test.js` | Threshold Log, English and French: the reference amounts on `shared/nutrition.js`; the line above the table in the app's own words (« Référence montrée pour »); the wrench asks sex, age, weight and the list, in words the app allows; a change moves the reference and is shared and kept; newer shared answers win, older ones don't, and what the app doesn't ask is kept; erasing removes them; and answers set in The Patch reach the Threshold Log on the same phone. | Browser |
| `../tools/stamp_cache.js --check` | Every app's offline cache carries the name of the file it holds. | Node |
| `apps/load.test.js` | Every page and app on the site loads, runs no script error, asks nothing of another site, and every link leads somewhere. | Playwright |
| `gut/one-food.test.js` | In the Food Trial Log, a bad day takes one food off the list, and undoing the report puts it back. | Playwright |
| `threshold/import.test.js` | The Threshold Log's import gives the same lists as the Food Trial Log's own screens, on five saved examples; from the browser, from a backup file, and from an old save. | Playwright |
| `threshold/screens.test.js` | Every screen and sheet of the Threshold Log, in both languages, on a 320-pixel phone: the words it never uses, French punctuation, nothing off screen, the keyboard, offline, the door, a day turning over, a day with nothing but water, the ticks on the label form, the rows of dots on the Threshold tab (one dot for each meal, the mark, the order, the card that says how to read them), unreadable saved data, and the web page (the count of compounds it gives, and the front page gives, is the engine’s; it opens on the front page’s question). | Playwright |
| `threshold/people.test.js` | Two made-up people use the Threshold Log for six weeks, one tap at a time. At the end every count on screen is checked against `threshold/oracle.js`, an independent recount that shares no code with the app. Every effect is opened, with the slider at 4 hours and at its two ends, and the meals listed before it are recounted. The Threshold rows are read off the screen one by one, for any effect and for one effect, with the slider at 4 hours and at its two ends, and checked the same way: a dot for each meal on its side, the mark and the counts on each side of it, the picture against those counts, the order of the rows (each kind of fat and sugar under its row), and the "5 compounds or more" line. The recount counts amounts closer than a thousandth of a row's highest as one amount, as the app does. No screen may carry a luck number: the opened line and the sheet of one food are read for one. One of the two drinks water and flavoured sparkling water as entries of their own, and has a label food whose form has "A flavour" ticked. | Playwright |

To run the screen tests on your own machine: `npm install --no-save playwright` and `npx playwright install chromium`, once.

The screens test also reads the how-to page, `threshold/how-soon/`: every time has a source to open, both languages give the same sources, and the app file holds no link to that page.

`fixtures/` holds saved Food Trial Log states from made-up people. `threshold/people.js` is the two people; everything they do is decided by a seeded random number, so every run plays the same six weeks.

Not tested here: a real iPhone. Installing, and bringing the Food Trial Log's lists into an installed app by its backup file, were tested in a desktop browser only.
